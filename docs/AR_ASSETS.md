# AR assets

Every 3D asset used by the AR Instrument Lab is listed here with its source and licence. Nothing ships without an entry.

## Why the models are generated, not downloaded

A `.glb` found on a model site usually cannot be shown to be licensed for this use: the licence is often unstated, inherited
from a parent work, or "free for personal use" — none of which is good enough for a government training platform. Rather than
ship an asset we cannot defend, the models here are **created in this repository** by a build script.

There is a teaching argument for it too. A schematic model with one named node and one material per component is better
training material than a photoreal mesh: the application can highlight exactly the part a trainee has to identify, and the
parts map one-to-one onto the database rows that drive the lesson.

### Doppler weather radar

```bash
npm run build:models      # regenerates the .glb from source
```

| | |
|---|---|
| Size | ~55 KB |
| Triangles | 2,316 |
| Vertices | 1,505 |
| Nodes / materials | 8, one per part |
| Height | ~1.2 glTF units (metres) |
| Textures | none — flat PBR materials only, so there is nothing to download or decompress |

**Parts** (the node and material names, which match `ARComponent.key` in the database):

| Node | What it represents | Interactive |
|---|---|---|
| `antenna` | Parabolic reflector, feed horn and support struts | yes |
| `radome` | Protective dome enclosing the antenna | yes |
| `tower` | Tapered support tower | yes |
| `receiver` | Receiver cabinet on the platform | yes |
| `rotator` | Pedestal that rotates the antenna in azimuth | yes |
| `controlUnit` | Radar control building at the base | yes |
| `platform` | Working platform at the top of the tower | scenery |
| `base` | Concrete foundation pad | scenery |

**Scale.** The model is about 1.2 m tall. glTF units are metres and AR places a model at its real size, so this is deliberately
a desk-sized scale model — a 30 m tower placed in a training room would be unusable. The interface says it is a scale model.

**Accuracy.** The geometry is a plausible schematic of a Doppler weather radar. It is **not** measured from, and does not
depict, any particular IMD radar, site or manufacturer's equipment, and it must not be presented as an engineering reference.

## Verified by hand

The 3D viewer needs WebGL and AR needs a camera, neither of which the automated tests have. These were checked in a browser:

| What | Result |
|---|---|
| AR placement on an Android phone (Chrome) | confirmed: camera starts, surface detected, radar placed |
| The `.glb` itself | confirmed: parsed and rendered offline while building it - 8 nodes, 8 materials, bounds and indices valid |
| Interactive 3D fallback in a desktop browser | **not yet confirmed by hand.** The code path is the same viewer with AR switched off, and the screens around it are tested, but nobody has clicked through it |

Re-check the AR flow by hand after changing the viewer or upgrading `@google/model-viewer`; no automated test can cover it.

## If you add a model

1. Prefer generating it in `scripts/build-ar-models.mjs` alongside the radar.
2. If you must use an external model, record the source URL, the exact licence (with a link), the author, and any attribution
   text the licence requires — then add the attribution to the AR lab's interface, not only to this file.
3. Keep it under roughly 2 MB and a few thousand triangles: these run on mid-range Android phones over mobile data.
4. Add a row to the inventory above in the same change as the asset.
